# CLAUDE.md

Orca plugins for working on GitHub from Orca's sidebar. Goal and feature list: `README.md`.
Plan: tracking issue #1, one sub-issue per step (#2 → #8).

## Layout

- `plugins/github/`: the only plugin so far, a `trusted-worker` with one components panel.
  - `src/worker.ts`: Node worker, wires the panel requests (`orca.panels.handle`) to the modules below.
  - `src/gh.ts`: `runGh` and `GhError` codes; every GitHub call goes through it.
  - `src/repo.ts` (+ `src/focus.ts`, `src/exec.ts`): the focused workspace's repo, `repo.get`, `repo.changed`.
  - `src/lists.ts`: one page of issues, pull requests (GraphQL search) or runs (REST).
  - `src/timeline.ts`: the timeline both share (GraphQL pages, cut to fit the message limit).
  - `src/issues.ts`: one issue (GraphQL body and timeline) and its writes (gh issue commands).
  - `src/pulls.ts`: one pull request (refs, merge state, review decision, checks, timeline with
    reviews and the merge), its writes (`gh pr comment`, `edit`, `review`) and the branch's pull
    request (`gh pr view`).
  - `src/panel.tsx`, `src/views.tsx`, `src/store.ts`, `src/look.ts`: components panel (`"ui": "components"`),
    no DOM, only the `orca` catalog; state in atoms; glyphs, tones and words.
  - `src/thread-store.ts`, `src/thread-view.tsx`: an open issue or pull request (a thread), one per
    tab, and the pieces both draw (posts, reactions, timeline, pickers).
  - `src/issue-view.tsx`, `src/issue-forms.tsx`, `src/issue-store.ts`: the issue detail, its forms
    and state; `src/pull-view.tsx`, `src/pull-store.ts`: the workspace's pull request (no list),
    its review, and the hand-offs to Orca's Tasks page and Checks tab.
  - `src/refs.ts`, `src/parts.tsx`: `#N` links, shared pieces.
  - `src/protocol.ts`: the panel ↔ worker contract (`PluginRequests`, `PluginPanelEvents`).
  - `src/*.test.ts(x)`, `src/panel.check.ts`: tests and render scenarios.
- `.orca/types/` is generated by `orca plugin types .` and gitignored; read it for the real API
  (host methods, components and their props). Do not guess an API that is not in there.

## Commands (from `plugins/github/`)

```sh
orca plugin types .        # (re)write typings, needed before tsc
orca plugin validate .
orca plugin test .
orca plugin check .
npx tsc -p .
orca plugin dev watch .    # load into Orca with live reload
orca plugin dev request . <name> --data '<json>'
orca plugin shot ...       # PNG of the panel as Orca draws it
```

All four checks (validate, test, check, tsc) pass before a PR.

## Rules

- Every GitHub call goes through the `gh` CLI already logged in on the machine. The plugin
  stores no tokens.
- Tests never call real GitHub: inject the `gh` runner and fake it.
- Limits to design around: `plugin.request` times out at 30 s by default (120 s max);
  `panels.post` payloads are at most 256 KiB; panel `Markdown` cannot load remote images.
- Destructive actions (close, merge, cancel, delete) ask for confirmation in the panel.

## Git and GitHub

- Branches: `main` and `dev`. PRs target `dev`; only `hotfix/*` or the `dev` → `main` release PR
  go into `main`.
- The repo is private under `chimeyrock999`, which may not be the active `gh` account. Pass its
  token per command instead of `gh auth switch`:
  `GH_TOKEN=$(gh auth token --user chimeyrock999) gh ... -R chimeyrock999/orca-github-plugins`.
